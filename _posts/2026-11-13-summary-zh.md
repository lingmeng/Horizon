### [Rust 1.100 发布：API 与 Cargo 更新](https://blog.rust-lang.org/2026/11/12/Rust-1.100.0/) ⭐️ 8.0/10

Rust 1.100.0 已发布（2026-11-12），把多个长期等待的稳定化 API 和若干重要的 Cargo/工具行为变更带入稳定通道，面向所有使用稳定版 Rust 的开发者和项目。主要变化包括稳定化 never 类型（\!）和自定义分配器（custom allocators）；在 Cargo 中引入“最小发布时间/依赖冷却”（minimum publish age，RFC 3923），解析器在启用该配置时会忽略比该阈值更新得更近的版本（除非该版本已存在于 Cargo.lock）；Cargo 现在默认向用户报告未使用的依赖警告；cargo install 默认使用发布包（.crate）内已有的锁文件，导致 --locked 在 cargo install 上变成无操作。 

hackernews · mbStavola · 11月12日 18:39 · [社区讨论](https://news.ycombinator.com/item?id=50472038)

**「背景」** Rust 的稳定发行包含语言、标准库和工具链（包括包管理器 Cargo）的一组兼容更改与修复。Cargo 使用 Cargo.toml 描述依赖并通过 Cargo.lock 固定解析结果；解算器和锁文件的行为决定何时以及如何采纳新发布的包版本，这一点是理解与“最小发布年龄/依赖冷却”等变更相关影响的前提。

**「影响与建议」** 因为 cargo install 现在优先使用 .crate 包内的锁文件并使 --locked 变为无操作，依赖可重复安装或可重现构建的项目需在发布时在包中包含适当的 Cargo.lock，或调整发布/安装流程；同时，任何依赖更新策略依赖“拉取最新版本”的 CI 配置应审查是否需要设置或调整最小发布时间阈值以避免意外回退或被解析器忽略新版依赖。

**「社区反馈要点」** 评论中有人对稳定化 never 类型和自定义分配器表示欢迎（用户 nirinor），并列出其它社区注意到的稳定 API（例如 bool::toggle、Box::map、str::trim\_prefix/trim\_suffix 等）；也有人对 Cargo 报告未使用依赖表示赞赏（用户 n\_u）。同时有用户（jadbox）指出仍关心编译速度和磁盘临时文件积累问题，这属于未在本次发布说明中解决的使用者痛点。

### [PostgreSQL 类型混淆原语被构造成 RCE（CVE-2026-6460）](https://mehmetince.net/part-3-6-how-i-ended-up-turning-a-22-year-old-postgresql-type-confusion-primitive-into-rce-cve-2026-6460/) ⭐️ 8.0/10

一篇技术复盘报告描述了如何把 PostgreSQL 中一个存在约 22 年的类型混淆（type‑confusion）原语开发成可导致代码执行的利用链，并以 CVE-2026-6460 记录。报告说明该利用链最终实现了在数据库宿主上执行代码（RCE），但文中与评论均指出这一路径可能需要经过已认证的数据库访问或特定的 SQL 权限。该细节把这次披露对多租户数据库、数据库管理员和安全团队的重要性与实际攻击前提（需数据库凭证或权限）区分开来。

hackernews · ozirus · 11月12日 18:22 · [社区讨论](https://news.ycombinator.com/item?id=50471761)

**「需要的先验概念」** PostgreSQL 在内部用 Datum 表示值，并把类型标识（type id/OID）与数据存放在不同位置；如果这两者不同步就会产生类型混淆（type confusion）风险。该报导把一个已存在约 22 年的类型混淆原语连成利用链并最终演示出可致操作系统级别代码执行的漏洞（CVE-2026-6460），但实现利用通常需要能在数据库中创建对象或其他已验证的数据库访问权限，这使得它更像是特权升级或多租户环境下的高危路径而非无条件的远程未授权入侵。 

**「直接影响与建议行动」** 对运行 PostgreSQL 的组织，特别是多租户环境，证据支持的后果是：持有数据库账户或被授予某些 SQL 权限的用户可能能借此途径将数据库访问升级为宿主服务器上的代码执行。建议的具体行动包括立刻审查并收紧数据库账号与角色权限（最小权限原则）、限制数据库的网络可达性、监控异常 SQL/权限使用并在供应商或维护方发布补丁或缓解措施时尽快应用。

**「社区反应要点」** 多名评论者（如 logophobia 和 jmuguy）认为此次利用更接近“权限升级”（privilege escalation）而非无需认证的远程入侵；其他评论者（如 igbanam、sailfast、amluto）则赞扬作者公开复现过程与对 PostgreSQL 内部 Datum/类型混淆细节的深入分析。
